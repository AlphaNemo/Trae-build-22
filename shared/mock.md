## 3. 假数据区（定题后填写）

> 按契约实际选用的接口保留对应小节，用不到的删掉。

### POST /chat（对话，一次性返回）

```json
// Request（契约照抄，供 D 对照）
{ "message": "这个药一天吃几次？" }
// Response（假数据）
{
  "reply": "药盒说明书写着：每日 3 次，饭后服用，每次 1 片。"
}
```

### POST /chat/stream（流式对话）

> 流式接口的假数据与 `/chat` 相同，由 B 负责把 `reply` 逐段吐出，D 只需准备文本。

```json
{
  "reply": "你面前是一瓶维生素 C，标签上写着每日 1 片，随餐服用。"
}
```

### POST /describe（上传图片 → AI 描述）

```json
// Request: multipart/form-data, field = file
// Response（假数据）
{
  "filename": "medicine_box.jpg",
  "size": 248120,
  "description": "这是一个白底蓝字的药盒，品牌名是“泰诺”，适用于头痛发热；盒子正面写着每次 1 片、每 6 小时一次，24 小时内不超过 4 次。"
}
```

### POST /transcribe（语音 → 文字，如选做）

```json
// Request: multipart/form-data, field = file
// Response（假数据）
{
  "text": "帮我看看窗外现在是什么天气。"
}
```

---

## 4. 逼真度要求（路演就靠它兜底）

- 描述要**具体、有画面感、适合语音朗读**：说清颜色、文字、数字、方位，不写「一个物体」这种空话。
- 长度贴近真实 AI 输出：图片描述 2–4 句，对话 1–3 句。
- 每个接口至少准备 **2 条**不同内容，避免演示时重复穿帮。
- 准备 1 条「异常降级」文案，接口失败时朗读，例如：「网络有点慢，我先根据已识别的内容告诉你：这是一盒感冒药。」
